# Way Mod — Fabric 1.21.11

Мини-мод для Minecraft **1.21.11** (Fabric Loader 0.20.1, Fabric API 0.141.6+1.21.11).
Версия мода: **1.1.0**. Языки: русский (`ru_ru`) и английский (`en_us`).

## Что в моде

### v1.0.0 — основа
1. **Блок перехода** (`way_block`): ПКМ по блоку — телепорт в заданное измерение/координаты. Shift+ПКМ — вернуться в точку, откуда был сделан последний телепорт.
2. **Крафтовый спавнер** (`craftable_spawner`): обычный спавнер, который **крафтится** из железных решёток и ока Эндера; моб задаётся командой или яйцом спавна.
3. **Команда `/way`** — выдаёт настроенные предметы и мгновенно переправляет игрока.

### v1.1.0 — Spawner 2000 Pro и логистика
4. **Спавнер 2000 Pro** (`spawner_2000_pro`) — автоматический спавнер от «Спавнеров 2 тысячи Pro Incorporated»:
   - спавнит **до 3 мобов за раз** (3 строки — по мобу в каждую), ставки живых существ: по умолчанию 10, максимум **150**;
   - обычный интервал — 5 секунд; прокачивается **ядрами скорости** до **0,5 секунды** (10 тиков);
   - **ядро убийцы**: заспавненные мобы автоматически умирают, а их добыча **размножается ×5** («Добыча 5» на пальцах);
   - моб задаётся `/way spawnerpro <моб>`, яйцом спавна (ПКМ по блоку) или `/way spawnerpro` + яйцо.
5. **Ядра прокачки** (предметы, расходуются по ПКМ по спавнеру Pro):
   - **Ядро скорости** (`speed_core`) — интервал spawns вдвое меньше; ставишь несколько — спавн каждые 0,5 с;
   - **Ядро вместимости** (`capacity_core`) — +50 к лимиту живых мобов (до 150);
   - **Ядро убийцы** (`killer_core`) — включает авто-убийство с добычей ×5 (ставится один раз).
6. **Авто-воронка** (`auto_hopper`) — собирает предметы **со всего чанка** (все предметы-сущности в границах чанка по всей высоте мира) и складывает их в **соседний контейнер** (сундук, бочка, другая авто-воронка — любые):
   - ПКМ **с предметом в руке** — добавить предмет в фильтр;
   - Shift+ПКМ с предметом — убрать из фильтра;
   - ПКМ **без предмета** — показать фильтр;
   - Shift+ПКМ без предмета — очистить фильтр;
   - **пустой фильтр = собирает всё**; заполненный — только перечисленное.
   Работает в связке с передатчиком (см. ниже) — можно строить сортировочные фабрики в чанке.
7. **Воронка-передатчик** (`hopper_transmitter`) — перекидывает ресурсы из сундука/воронки **в другой контейнер** (свой, соседний, на другой стороне склада):
   - **Shift+ПКМ** по передатчику (с пустой рукой или с любым предметом — не важно) — «прицелиться»;
   - затем команда **`/way link <координаты>`** (координаты поддерживают `~`) привязывает цель: ближайший на прицеле контейнер по координатам;
   - дальше каждые 10 тиков передатчик тянет предметы из контейнера **за ним** (или любого соседнего) и вставляет в **привязанный** контейнер;
   - передатчики работают и с авто-воронками: авто-воронка складывает в сундук, передатчик тянет из сундука и отправляет на склад.
8. **`/way spawnerpro <моб>`** — выдаёт Спавнер 2000 Pro сразу с заданным мобом.

## Команды

| Команда | Что делает |
|---|---|
| `/way give <измерение> <x> <y> <z>` | Выдаёт блок перехода с записанной целью телепортации |
| `/way set <измерение> <pos>` | Задаёт цель существующему блоку перехода на позиции (координаты поддерживают `~`) |
| `/way spawner <моб>` | Выдаёт крафтовый спавнер с выбранным мобом |
| `/way spawnerpro <моб>` | Выдаёт Спавнер 2000 Pro с выбранным мобом |
| `/way link <pos>` | Привязывает передатчик (после Shift+ПКМ по нему) к контейнеру на позиции |

Примеры:

```
/way give overworld -1412 69 121
/way give nether -1412 69 121
/way give the_end -1412 69 121
/way give minecraft:overworld -1412 69 121   ← то же самое, полный id
/way set nether ~ ~-2   ← задать цель блоку перехода на 2 блока южнее-севернее (по взгляду ~)
/way spawner zombie     ← можно и minecraft:zombie
/way spawnerpro minecraft:wither_skeleton
/way link ~ ~3 ~        ← привязать передатчик к сундуку на 3 блока выше
```

Псевдонимы измерений: `overworld`, `nether`, `the_end`; можно указывать и полный id (`minecraft:overworld`, `minecraft:the_nether`, `minecraft:the_end`).

Права: все команды уровня «команды модератора» — полу-операторские (как `/gamemode`), то есть требуется оператор.

## Как работает телепорт

- ПКМ на **блоке перехода** (не сидя):
  - если у блока есть цель — телепорт в место цели: вы появитесь на полу блока с координатами `x+0.5, y, z+0.5`, поворот камеры сохраняется;
  - точка, где вы стояли перед телепортом, запоминается (при смерти сохраняется тоже);
  - **Shift+ПКМ** по любому блоку перехода — вернуться в запомненную точку.
- Если у блока ещё нет цели — подсказка сообщит об этом.

## Как жить со Спавнером 2000 Pro

1. Поставьте блок (`spawner_2000_pro`) или получите готовый: `/way spawnerpro zombie`.
2. Моб ставится:
   - командой при выдаче (`/way spawnerpro zombie`), **или**
   - ПКМ по блоку **яйцом спавна** (например, яйцо зомби), **или**
   - `/way spawnerpro` + яйцо — комбинировать не обязательно, но можно.
3. Прокачка ядрами — просто **ПКМ по блоку с ядром в руке**:
   - ядро скорости: интервал /2 (5 с → 2.5 с → 1.25 с → 0.625 с … минимум 0.5 с);
   - ядро вместимости: +50 (10 → 60 → 110 → 150 — потолок);
   - ядро убийцы: один штук — включает режим «фарм».
4. **Ядро убийцы + авто-воронка = ферма без рук**: мобы спавнятся, умирают, добыча ×5, воронка собирает её **со всего чанка** в сундук, передатчик дотягивает до склада.
5. Спавн продолжается, даже если игрок отошёл (тик блок-сущности работает в загруженных чанках; лимит живых считается в области ±8 блоков по X/Z).

## Крафты

Блок перехода (обсидиан + жемчуг Края + око Эндера):

```
[O P O]      O = обсидиан (minecraft:obsidian)
[O E O]      P = жемчуг Края (minecraft:ender_pearl)
             E = око Эндера (minecraft:ender_eye)
```

Крафтовый спавнер (железные решётки + око Эндера):

```
[# E #]      # = железная решётка (minecraft:iron_bars)
[# # #]      E = око Эндера (minecraft:ender_eye)
```

Спавнер 2000 Pro (золотая рамка вокруг крафтового спавнера):

```
[# E #]      # = железная решётка
[G # G]      E = око Эндера
             G = золотой слиток (minecraft:gold_ingot)
```

Авто-воронка (железный слиток + воронка):

```
[I H I]      I = железный слиток
             H = воронка (minecraft:hopper)
```

Воронка-передатчик (жемчуг Края + воронка + редстоун):

```
[P H P]      P = жемчуг Края
[R H R]      H = воронка
             R = редстоун (minecraft:redstone)
```

Ядро скорости (редстоун + око Эндера):

```
[R R R]      R = редстоун
[R E R]      E = око Эндера
```

Ядро вместимости (железо + око Эндера):

```
[I I I]      I = железный слиток
[I E I]      E = око Эндера
```

Ядро убийцы (решётки + железо + око Эндера):

```
[B I B]      B = железная решётка
[I E I]      I = железный слиток
             E = око Эндера
```

Точные JSON лежат в `src/main/resources/data/waymod/recipe/` — правятся датапаком без пересборки.

## Установка готового мода

1. Убедитесь, что стоит загрузчик Fabric и Fabric API **0.141.6+1.21.11** (версия API указана в `gradle.properties`).
2. Скачайте/соберите мод (см. ниже) — файл `build/libs/waymod-1.1.0.jar`.
3. Положите jar в папку `mods` и запустите игру.

## Сборка из исходников

Нужно: **Java 21** (например, Adoptium Temurin 21) и интернет (первая сборка скачает Minecraft ~1 ГБ, потом используется кеш).

Windows:
```bat
gradlew.bat build
```
Linux/macOS:
```sh
./gradlew build
```

Готовый jar появится в `build/libs/`. Заодно собирается `-sources.jar` — это нормально.
Если что-то пойдёт не так: `gradlew.bat clean build`, либо `gradlew.bat --stop` (убить демоны Gradle и попробовать снова).

Текстуры можно перегенерировать (уже сгенерированы):
```bat
powershell -ExecutionPolicy Bypass -File tools\make_textures.ps1
```

## «Смена модов без рестарта» — как есть

Честно: **полностью подгрузить мод без перезапуска игры невозможно** — ни в Fabric, ни в Forge/NeoForge. Это не особенность загрузчика, а устройство самой игры и Java. Вот почему:

1. **Java нельзя «выгрузить» класс.** Загрузчик классов JVM загружает класс один раз и навсегда — с ним связаны объекты, поток, статические поля. Удалить или заменить класс на лету JVM не умеет (это архитектурное ограничение платформы, а не Fabric).
2. **Реестры Minecraft замораживаются.** Блоки, предметы, сущности, компоненты данных регистрируются в глобальные реестры (`Registries`), которые после загрузки игры **закрываются на запись**. Это сделано для стабильности: иначе мир и чанки со старыми блоками перестали бы корректно сохраняться/загружаться (id блоков в чанках хранятся по номерам в реестре).
3. **Мир держит ссылки на загрузчик.** Уже загруженные чанки, сущности, тайл-энтиты, слушатели событий Fabric — всё это живые объекты, привязанные к коду мода. «Вытащить» мод = обрушить эти ссылки → краш.

**`/reload` не спасает:** он перечитывает только *данные* (датапакеты): рецепты, лут-таблицы, достижения, функции, теги. Именно это знание — та самая «замена мода без рестарта».
Кстати, это работает и для данных **этого** мода (`data/waymod/recipe/...`): их можно переопределить файлом в мировом датапаке — `/reload` подхватит без рестарта.

**Клиентский `F3+T`** перечитывает *ресурсы*: текстуры, модели, blockstate, звуки, языки. Код он не трогает.

### Что реально МОЖНО сделать «без рестарта»

| Что хотим | Можно? | Как |
|---|---|---|
| Поменять рецепт/лут | ✅ | `/reload` (или файл в мировом `datapacks/`) |
| Поменять текстуру/модель/звук/язык | ✅ (клиент) | `F3+T` |
| Поменять **код** (блоки, поведение) | ❌ | только рестарт игры/сервера |
| Добавить новый блок/предмет в живую игру | ❌ | реестры заморожены |

### Ускорители: «чтобы грузило так — и не крашило»

Раз «горячей подгрузки» нет, разумнее всего ускорить сам рестарт:

1. **Запуск сразу в мир** (минуя главное меню):
   - одиночная игра: аргументы запуска `--quickPlaySingleplayer <имя_мира>`;
   - сервер: `--quickPlayServer host:port`.
   Это самый заметный «ускоритель» по времени.
2. **Быстрый путь для ресурсов**: в 1.21.x перезагрузка ресурсов и так асинхронная, но убедитесь, что в наборе ресурсов нет тяжёлых паков (сотни МБ).
3. **JVM-аргументы**, которые помогают запуску:
   ```
   -Xms1G -Xmx4G
   ```
   (не ставьте -Xms равным -Xmx огромным значением — стартуют дольше аллокации).
4. **Меньше модов = быстрее**. Метод «включать только нужное» — Fabric плевать не заставит загрузить лишку.
5. **SSD и чистый кеш**: ~/.gradle на SSD; при странных зависаниях — `gradlew --stop`.
6. **В dev-среде (IntelliJ IDEA)**: правки *тела* методов можно применять **HotSwap** (`Build → Apply modified classes` / `F9`) без рестарта `runClient`.
   Правки уровня «новый класс/новая регистрация» всё равно требуют рестарта — см. причины выше. DCEVM/JBR-расширения теоретически умеют больше, но с remap-версией Minecraft это «лотерея с крашами» — не рекомендую использовать: вы именно этого и не хотите («чтобы не крашило»).
7. **Эмуляция «смены модов» внутри мода**: писать фичи как включаемые через конфиг (настройки + события проверяют включённость). Тогда «отключить/включить фичу» — это конфиг + `/reload` (если это данные) или просто рестарт сервера — но без «разрушения» мира. Это самый надёжный способ получить ощущение «мод без рестарта».

Прямая связь к вашему запросу: «только чтобы не крашнуло и грузило так» — значит-то это и есть реальные ускорители: **дата-паки и ресурсы — горячо; код — рестарт, но умеренный и быстрый**.

## Если компилятор ругается (фиксер-таблица)

Код написан под официальную версию 1.21.11 с маппингами **Mojang** (включены в `build.gradle`).
Маппинги между версиями в мелочах различаются. Ниже — точечные правки по одному слову, если `gradlew build` вдруг не пройдёт compile.

1. `net.minecraft.world.entity.TeleportTarget` не найден →
   попробуйте `net.minecraft.world.level.portal.TeleportTarget`
   или кратко определите класс через поиск (Ctrl+N в IDEA: «TeleportTarget» / «TeleportTransition»).
   Также метод может называться `player.teleport(...)`, `player.teleportTo(...)` или `player.changeDimension(...)`.
   Точка правки: файл `WayTeleport.java`, метод `teleport(...)` — **одна строка мода**.
2. `useBlockDescriptionPrefix` → если нет, попробуйте `useItemDescriptionPrefix()` или удалите строку (появится только немного другой ключ перевода).
3. `postPlacement(...)` в `WayBlockItem`/`CraftableSpawnerItem` → может называться `placeBlock(...)` или `onBlockEntitySet(...)`.
4. `BlockEntity.createTickerHelper(...)` → может называться `createTickerHelper`/`createBlockEntityTicker` (в классе `BlockEntity`).
5. `SpawnerBlockEntity::clientTick` / `::serverTick` → это статические методы, ищите с точной сигнатурой
   `clientTick(Level, BlockPos, BlockState, SpawnerBlockEntity)`.
6. `getSpawner()` / `setEntityId(...)` → альтернативы: `getLogic()` (yarn), `getSpawner(...)`; для моба: `setEntityId(EntityType, Level, RandomSource, BlockPos)`.
7. Методы `ValueOutput`/`ValueInput` (`putString`, `putInt`, `getStringOr`, `getIntOr`) → в самых старых версиях назывались с CompoundTag (`saveAdditional(CompoundTag)`).
8. `source.permissions().hasPermission(Permissions.COMMANDS_MODERATOR)` → альтернатива напрямую: `source.hasPermission(2)`.
9. `source.playerOrException()` → возможно `getPlayerOrException()`.
10. `player.addItem(stack)` / `player.drop(stack, false)` → альтернатива: `player.getInventory().add(stack)`.
11. `player.isShiftKeyDown()` → возможно `isCrouching()`.
12. `server.levelKeys()` → возможно `server.getLevels()`; ищите нужный метод со словом «level» в названии.
13. `SpawnReason.SPAWNER` → в части версий `SpawnReason.SPAWNED`; место: `ProSpawnerBlockEntity.tick`, строка `type.create(level, ...)`.
14. `DamageSources#genericKill()` → возможно `generic()`; место: `ProSpawnerBlockEntity.killAndHarvest`, одна строка `mob.hurt(...)`.
15. `ItemEntity#set(ItemStack)` → возможно `setItem(...)`; `item.discard()` → возможно `kill()`/`discard()` — место: `AutoHopperBlockEntity.tick`.
16. `level.getMinBuildHeight()/getMaxBuildHeight()` → возможно `getMinY()/getMaxY()` — место: `AutoHopperBlockEntity.chunkBoxOf`.
17. Если вы переключите маппинги на **Yarn**: класс `ResourceLocation` станет `Identifier` (метод `fromNamespaceAndPath` тот же), `getSpawner` станет `getLogic`, `BuiltInRegistries` — `Registries`.
18. В клиентских тултипах, если Fabric API в вашей сборке выдал `Consumer<Component>` вместо списка: замените `lines.add(...)` на `lines.accept(...)`.

Идея упорная: **вся «хрупкая» телепортация собрана в одном файле `WayTeleport.java`** — даже если что-то уедет в будущей версии, чинить надо один маленький класс.
